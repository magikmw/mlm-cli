## 1. Summary

The live docs and two `--help` strings have drifted from the shipped
code. After this changeset README, `--help`, SPEC.md, AGENTS.md,
NOTES.md's header and `docs/dev/README.md` state what the code does,
SPEC.md covers `delete` and backdated `TIME` on its own, and every
archived file carries its banner.

## 1.1 Non-goals

- No behavior change. The only output change is the two `--help`
  strings in §3.
- F21 (`mlm week 0999-05` names the week number, not the year) stays as
  it is.
- The numbered NOTES.md log stays as written, apart from the F4 pointer.

## 4. Internal fixes

- **F4**: SPEC.md gains the `delete note|punch` surface as
  `src/commands.rs` ships it. The archived delete spec
  (`docs/dev/specs/2026-09-13-delete-punches-notes.md` §3-§5) is a
  starting point only, and the code wins wherever they differ:
  - §3.9 (command): arguments, list mode, punch tie ordering, the
    singular/plural `entry`/`entries` wording, `--date` in the recreate
    line only for another day, `stop` for an `end` punch, single-quote
    shell quoting, the stale-id rule, and clap's exit-`2` rejection of
    a non-numeric `ID`
  - §6.1: the two `ID` errors, quoted
  - §7.4: the list and recreate formats
  - §8.2: one E-entry per `ID` error
  NOTES decision 5 already points at §3.9 (landed in `3a396c0`).
- **F5**: SPEC §3.2/§3.4a state that `TIME` is required when `--date`
  names another day, and §6.1 quotes `TIME is required when --date
  targets a day other than today`.
- **F6**: every archived file under `docs/dev/specs/`, `docs/dev/plans/`
  and `docs/dev/plans/reports/` without a banner gets one, after its
  title line. Specs take the spec banner, plans the planning banner,
  reports the existing report banner (`> **Archived — historical
  review/report record.** Not authoritative. Current spec:
  `docs/dev/SPEC.md`.`). A file with no title line takes the banner as
  its first line. This changeset's own docs are excluded: this spec,
  `doc-drift-sweep-review.md`, `doc-drift-spec-review.md` and any later
  `doc-drift-*` report. The coordinator banners them at close-out.
- **F7**: `docs/dev/README.md` says the banner points to `SPEC.md`,
  names `plans/reports/` as archived, and says a changeset's close-out
  banners its spec, plans and reports.
- **F10**: AGENTS.md lists the five shipped targets (Linux x86_64 and
  ARM64, Windows MSVC, macOS Intel and Apple Silicon), and "on either
  platform" in the same sentence becomes "on any of them".
- **F15**: SPEC.md's and NOTES.md's headers say what each doc is now.
- **F16**: SPEC's data model names the two composite indexes and
  `user_version`, and drops the scaffold reference.
- **F17**: SPEC §6.1's read-failure list gains `status`'s note read and
  its lookback read.
- **F18**: SPEC says "the three entries just before the `[!], [i]` one".
- **F19**: AGENTS Layout names storage's per-date reads and deletes, and
  puts the exit-code mapping, `OutputError` and `emit` in `lib.rs`.
- **F20**: code comments under `src/` follow one rule. An unqualified
  `spec §N` or `SPEC §N` names a SPEC.md section, and that section
  holds what the comment says. A citation of an archived doc (PLAN.md,
  its milestones and interface contracts, a changeset spec) is
  rewritten to cite SPEC.md, or dropped when the comment stands
  without it. Task 1 finds the sites by grep. The review's table
  (`doc-drift-spec-review.md` R4) and the sweep's F20 list are the
  known ones. Other false statements in those comments are fixed too:
  `src/time.rs`'s dead-code note (and its `#![allow(dead_code)]` if
  nothing it covers is dead), `src/status.rs:525`'s §7.4 claim,
  `src/date.rs`'s `Month` domain note.
- **F3 follow-ons**: `Cargo.toml`'s binstall comment and
  `.github/workflows/sign-artifacts.yml` cite `docs/SIGNING.md`.
- **Package contents**: `Cargo.toml`'s `exclude` list uses pre-move
  paths, so the published crate ships `docs/dev/` (SPEC, NOTES, every
  archived spec). `exclude` names `docs/dev/` instead, and
  `cargo package --list` shows no file under it. `docs/SIGNING.md`
  stays in the package.
